# 从签字厅走进《雅典学院》：入口研究与方案

状态：2026-10-22 完成官方资料核实、实景观察和现有代码的只读审查。本文件是入口体验方案，尚未改写 Unity 程序；P0 冻结成果保持原状。

## 已核实的真实场所

- 《雅典学院》位于梵蒂冈博物馆参观体系中的拉斐尔画室，具体是签字厅／Stanza della Segnatura（Room of the Segnatura）。
- 拉斐尔画室属于宗座宫的房间组。官方房间介绍明确：签字厅原为尤利乌斯二世的私人图书馆和办公空间，后来因教廷最高法庭在此开会而得名。因此入口应参考真实宫室／展厅，而非另造一座泛化教堂。
- 房间的壁画主题关联真、善、美；《雅典学院》代表哲学／理性之真。邻墙、拱顶和地面共同构成展厅环境。
- 实际查看官方签字厅总览图：壁画位于墙面上方，下面有装饰墙裙；同一面墙左下有门洞；房间具有装饰拱顶、邻墙壁画、窗和拼花地面。不能将完整壁画直接缩放成一扇贴地的普通门。
- 官方对作品的介绍指出，画中宏大文艺复兴建筑受到布拉曼特圣彼得大教堂更新方案启发。真实签字厅与画中建筑应分别建模；穿画是项目创作的空间连接，不是声称存在历史通道。
- 尚无本轮可核验的精确房间尺寸、相机标定或完整测绘，先做基于实景关系的研究性重建，不标为尺寸准确的数字孪生。

## 建议体验

主线：现实展厅中的观画者 → 走近壁画 → 画面显露纵深 → 穿越画面 → 画中学院的参与者。

1. **展厅首页。** 镜头位于签字厅内的略偏侧站位，同时看到壁画墙、部分邻墙、地板和天顶，先让人认出这是一幅画在墙上的壁画。此机位为体验设计，不冒充已考证的真实参观入口站位。
2. **走近。** 开始漫游后在展厅短距离移动。到达壁画前有效范围时出现“走进画中”提示，主动触发，避免碰墙即被意外传送。
3. **对准并穿画。** 建议约6—8秒的受控镜头小样：镜头平缓推进、必要时轻微升高，对准画中固定透视中心；局部绘画逐渐显出学院的空间深度，随后让壁画边界从视野边缘退去。声音可从室内回响逐渐变为画中环境声。首版不依赖复杂动态 Portal 系统或夸张旋转镜头。
4. **落地与交还控制。** 镜头继续走到学院有效地面上的漫游起点，将位置、朝向、FOV及投影偏移平滑过渡后交还控制。第一步前进必须从最后一个自动镜头的位置继续。
5. **返回。** 提供清楚的返回展厅入口和再次进入流程。首次先以明确的返回操作完成闭环，双向实时可见的动态传送门不作为首版必要条件。

展厅只制作一间房及壁画附近必要关系，先验证体验。当前学院仅一名静态人物，原画群像与三维场景尚不完整，不能预先保证整幅原画无缝变成立体画面；需用实际前／中／后帧测试局部揭示与接缝。

## 最小技术方向与现有实现约束

- 优先同一 Unity 场景内分区域制作展厅和学院，预先准备好学院；使用受控镜头和画面／材质混合，避免穿越中途加载造成停顿。无需首轮增加通用场景管理框架。
- 现有单相机、CharacterController、学院主构图及四个检查机位可以复用；展厅、壁画材质、触发区、转场状态、跳过和返回均需新实现。
- 现有 `BeginRoaming()` 会重设位置到 `(0,.04,-5)`、眼高1.65m、FOV57并重置投影，不能直接在转场结束时调用。新增从当前合法站位交还控制的专用入口。
- 画中 P0 对应固定裁切 `[128,128,1024,768]` 和偏移投影；完整壁画、展厅斜视和学院主视图需要显式标定关系，不能直接整图淡出替换。
- 明确状态：展厅待机 → 展厅漫游 → 对准／穿画 → 学院漫游 → 返回。自动转场时只有一个模块写相机，现有1—4、R、Enter与鼠标环视需按状态路由。
- `ProductionBuilder.CreateScene()` 会重建场景，入口结构必须接入生成器；不能只手动加在现有场景里，避免重建丢失。
