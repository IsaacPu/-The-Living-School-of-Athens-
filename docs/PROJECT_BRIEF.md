# P0：原画结构与一人合模样板

2026-10-22。用户已明确授权项目负责人自主推进，并要求第一性原理与对抗性审查。

## 本阶段要证明什么

观众需要认出《雅典学院》的中央空间，并能走近一名真实人物。我们先证明原画投影关系、近距离空间和独立资产集成可控，再扩大美术生产。

本阶段交付是**正式项目内的建筑/人物技术样板**，不是完整原画复现，也不默认意味着脸手已经精修通过。当前不增加 LLM、语音、全人物或付费生成。

美术主线为原画色彩的绘画写实。原画决定构图、服色、人物手势与书籍；真实建筑、雕像、解剖和服饰资料辅助解释结构。画外部分及不能同时成立的绘画透视需明确记录设计补全。

## 第一性原理与否决条件

| 必须证明 | 证据 | 否决情形 |
| --- | --- | --- |
| 原画纵深与中央构图可控 | 锁定裁切、机位、6—8 个构图锚点；实际主视图与参考对照，记录偏差 | 改裁切/机位掩盖比例问题；只有参数没有对照 |
| 走近后空间仍成立 | 近景、侧视、回望；真实可达路径与碰撞检查 | 台阶无法通过、穿插、掉落、背面完全缺失 |
| 人物资产可核查 | 原件哈希、可编辑源、正侧背与脸手检查图、缺陷清单 | 仅远景；把平滑/细分或转格式称为脸手精修 |
| A/B 能在独立工程集成 | 新 Windows 程序、实际模型路径与哈希、真实材质和落脚截图 | 运行时读 test-project；缺贴图；重复 180°旋转；借用旧40项报告 |

几何锚点偏差可先以画宽约 3% 观察，误差必须实测；该数字不是美术验收的替代。没有真实改善时保留原件并报告缺陷，不制造已精修的结论。

## 交接契约

- 共享配置为 `config/project.json`，由负责人维护。正式端口 8788；本阶段不启动后端。
- B 的交接文件为 `art/characters/plato/v001/delivery.json`；A 在自己的 Unity 工程内建立独立导入副本，不能改写 B 文件。
- 单位为米。GLB 使用 +Y 向上、+Z 为人物正前；必须用检查图验证实际面向，无法验证时写 pending，不猜测。
- 导出人物脚底落在 Y=0，身体体尺按脚底到头顶记录；举手后的整体包围盒另记。不再统一缩放至 2.1m。
- 人物原始 GLB 保留只读副本，修改另存；材质贴图完整打包。当前母版是无骨骼静态模型，不承诺可换装/可绑定。
- `delivery.json` 至少包含 schema_version=1、asset_id、relative_glb_path、sha256、bytes、source、units、up_axis、forward_axis、orientation_verified、body_height_m、bounds_m、triangles、materials、skins、animations、relative_blend_path、qa_images、changes、known_defects、technical_status、art_status。路径均相对该清单。
- 原模型若仅完成坐标/原点/材质整理，应标为 `baseline_diagnostic`，不能标为精修人物。geometry_changed 与变更说明要准确。

## A：场景任务 A-P0

独占 `unity/`、`art/environment/`、`scripts/environment/`、`qa/environment/`。

1. 初始化独立 Unity 6000.0.85f1 / URP 17.0.4 / glTFast 6.20.0 工程。可以复制经核实的最小配置并记录来源；不复制 Library、Builds、原型自动 Bootstrap 或整套旧场景。
2. 建立中央纵深拱廊、必要墩柱、台阶与格状拱顶样段；至少一组构件具备真实厚度/倒角和可调参数。避免再做横向三拱门庭院。
3. 主相机机位与裁切要明确记录，并输出参考锚点对照；保留可走近和回望空间。第一轮只宣称灰盒/结构样板。
4. 按 B 清单复制导入一名人物；B 未交付前可用明确标记的占位，最终 P0 不能只有占位。
5. 建立正式产品身份与自己的构建/日志路径。本阶段不依赖问答服务，绝不自动连 8787。
6. 交付可运行 Windows 样板、启动入口、至少主视图与近景的真实渲染、可重复构建或导入入口、检查报告和已知差距。主动做反例检查。

## B：人物任务 B-P0

独占 `art/characters/`、`scripts/characters/`、`qa/characters/`。

1. 将已验收 Lux3D 柏拉图复制到独立 source 目录，记录原始任务 4277623、文件哈希和来源；不得修改测试原件。
2. 用负责人准备的 Blender 便携环境导入 GLB，制作真实正、左右侧、背、脸与手检查图，形成有图定位的缺陷清单。不得用概念图替代资产检查。
3. 建立可打开的 .blend、脚底原点与实际朝向/标尺正确的 GLB 诊断版；只做有证据、可回退的变更，重点检查材质是否错误金属感、几何断裂/穿插、持书与手指。
4. 原画指天手势、书籍、脸部辨识等未达到时如实标出。头手解剖难题不得用全局平滑或细分伪装完成。若可靠局部修改不足，先保留原几何作为合模样板，提出下一轮局部重建路线。
5. 提交 delivery.json、变更前后同条件比较、参考来源表和复现脚本。无新 Lux3D 任务、无新 API 调用、无采购。
